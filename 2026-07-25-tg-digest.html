阿里开源的 page-agent：一行 <script> 就给任意网页装上 AI Agent。

总 star 27,525，fork 2,411，Trendshift 收录。最新版本 v1.12.2，昨天还在提交代码，31 页贡献者。

它解决的是「网页 Agent 太重」这个问——现在做浏览器自动化，基本都要装 Chrome 插件、跑 Python、起 headless 浏览器，用户端根本落不了地。page-agent 反过来做：纯页面内 JavaScript，不装插件、不开后端、不截图。

文本化 DOM 操作 — 不走截图路线，因此不需要多模态大模型，也不用申请特殊权限

自带模型接入 — 主流模型都能接，包括本地部署的（README 示例用的是 qwen3.5-plus）

可选 Chrome 扩展 — 需要跨标签页的多页面任务时再加，不是必需

MCP Server（Beta） — 让外部 agent 客户端反过来控制你的浏览器

npm 直接装 — npm install page-agent，两行代码 agent.execute('点击登录按钮')

它明确说了自己的定位是客户端网页增强，不是服务端自动化，DOM 处理和 prompt 部分基于 browser-use 改的，MIT 协议。

适合：

做 SaaS / ERP / CRM 后台，想给产品塞个 copilot 但不想重写后端的

表单流程长到 20 次点击起步，想压成一句的内部系统团队

做无障碍访问，需要让网页能被自然语言驱动的

做 AI 内容最亏的，不是不会写，而是每天先被信息流打散：这边 OpenAI 发了东西，那边 Anthropic 又上新，刷了两小时，最后只留下一句“今天没啥可发”。

AI 前哨干的不是替你瞎编爆文，而是把这个前置动作收成一条流水线：盯官方一手动态，做中文策展，直接渲染成小红书竖图和公众号长图，再放到一个 GitHub Pages 审核页。你每天看到的不是一堆链接，而是可判断、可挑选、可二次加工的内容半成品。

以前大家以为做 AI 资讯号的门槛是会写提示词。真正的门槛其实是：你有没有稳定信源、能不能避开重复新闻、能不能在热点凉掉前把它变成适合自己账号的表达。没有这套前哨，内容像临时捡；有了它，至少每天有一份待挑选的选盘。

它现在默认抓 Anthropic 和 OpenAI 的公开动态，还能扩展来源。生成后，小红书是一组 6 张竖卡，公众号是封面加正文长图；最后发不发、怎么改标，仍然由人自己定。这一点反而靠谱：平台发布最后一步不自动替你按，避免把“自动化”做成批量复制。

想用得别翻车，记住四件事：

  1. 别把卡片原样搬运。官方公告翻成中文，不等于已经是你的观点。至少补一句“这对谁有用、谁别追”，账号才有判断。

  2. 一定先锁信源。这个仓库的价值是“一手来源→中文内容”，不是把全网二手搬运再加工。你做设计、投资研究或创业，就加自己的可信来源。

  3. API Key 只放 Secrets。仓库本身是公开的，密钥和私密选不要塞进文件里。

  4. 别跳过审核页。今天模型把一个产品更新理解错了，发出去就是你账号背锅。先在手机上看卡片，再决定是否进草稿箱。

说白了，以前是等热点砸到脸上才临时找角度；现在是每天先收到一盘经过筛选的“内容毛坯”，你只把精力花在最值钱的判断和表达上。

适合盯 AI、科技和产品动态的个人号、公众号和小团队；只想一键批量发号的人别折腾。第一步就是先把它装成 Skill，跑一次 mock 预览，再接入自己的官方信源。

为什么演示-销售-建造这么有效？

其实背后的商业逻辑其实很简单：创业最大的风险不是技术风险，而是市场风险。

你可以用最好的技术做出最完美的产品，但如果市场不需要，一切都是白搭。

Uber、Dropbox、Figma和Slack都是从MVP开始成为独角兽的。这些公司的共同点是，都在早期通过简单的演示或原型验证了核心假设，然后再投入大量资源进行开发。

即使演示失败了，也比直接开发产品失败要好得多。

比如Segway，这个在2002年被预言将改变城市结构和人类思维模式的产品，最终却不温不火。

主要原因是路权问和实际使用场景的限制，但如果当初先通过简单的演示验证市场接受度，可能会发现这些问并及时调整方向。

卖空气其实不是真的在卖空气，而是在验证空气是否有市场。如果连空气都卖不出去，又何必花时间去造一台制氧机呢？

开放权重的定义与作用：开放权重模型允许任何人下载、检查、修改并在自己的基础设施上运行，使先进 AI 技术更具可及性、适应性和普及性。
