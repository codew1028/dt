他们做了几组实验，发现模型越聪明，通常就越擅长判断哪些信息值得记住，也更善于把过去的经验转化为未来能够复用的规则。

所以，同样一套记忆系统，在不同模型手里，效果可能差别很大。

第二，人脑的记忆机制确实非常精妙，Anthropic 也在尝试借鉴人脑的记忆机制，来设计 Agent Memory。

大家可以想一下，我们在日常生活中，其实一直在不断形成新的记忆，同时又在不断遗忘。

人脑的海马体在记忆形成过程中发挥着重要作用，可以帮助我们快速记录当下的经历。但人脑又不会把所有经历都原封不动地保存下来。

在睡眠或者安静休息的时候，大脑也没有停止工作。

海马体会重新激活我们之前经历过的一些神经活动模式，这个过程叫记忆回放（Memory Replay）。它会把近期经历中的部分信息，逐渐整合进更加稳定的长期记忆中。

Agent 不可能在每次新 Session 开始时，就把所有历史记忆全部加载进上下文。

即使搜索到了，也需要重新梳理这些信息之间的关系。随着记忆越来越多，这个过程的成本也会越来越高。

所以，Anthropic 又设计了第三层，Memory representations，记忆表示。

Memory representations 具体的实现方式其实很简单，就是 Wiki（更准确的说，Wiki 是其中一种实现方式）。大家可以把它理解成一套由 AI 自动整理和维护的知识库。

这比每次都从大量历史文件里重新寻找信息，要方便得多。

在这个基础上，还有第四层，叫 Injected context。

Dreaming 会把特别重要的记忆提升到这一层，由 Harness 在新 Session 开始时自动加载。这样，Claude 不需要主动搜索或者查找 Wiki，就能直接看到这些信息。

但 Context 是非常宝贵的，不可能把大量记忆都加载进去。

所以，这一层除了保存少量重要记忆，还会放一些记忆索引，告诉 Claude 已经记住了哪些信息，以及更详细的内容保存在哪里。

理解了这四层记忆的结构，我们再接着讲 Dreaming。

简单来说，Dreaming 就是利用 Agent 空闲的时间，重新整理过去 Session 留下的原始记录，更新和维护整个记忆系统。

举个很简单的例子。

Agent 在平时的会中，可能直接把一些重要信息写进 Memory Notes，但当时记录的信息未必准确。比如，我告诉 Claude，自己喜欢红色。它判断这是一条重要信息，于是保存到了记忆里。

但是过了一段时间，我在另外一个 Session 中又提到，自己现在更喜欢绿色了。如果之前的记忆没有及时更新，就可能出现前后不一致的问。

怎么办呢？

Dreaming 会检查不同 Session 的原始记录，然后更新 Memory Notes。如果没办法确认，也可以先把这条信息标记为存疑，避免后面继续使用错误的记忆。
